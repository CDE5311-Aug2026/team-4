# HDB 绿意邻里

依据《HDB Eco Community GDD V1.0》制作的 Three.js 单情景游戏原型。玩家管理一个已经有人居住的组屋社区，在有限预算和土地中建设公共绿地、改造住宅、实施政策，并接受一次提前预告的热浪和项目验收。所提供的概念图作为社区氛围与信息层级参考。

## 运行

需要 Node.js 22 或更高版本。项目使用固定版本的 Three.js 与 Vite。

```sh
pnpm install
pnpm dev
```

也可使用 `npm install`、`npm run dev`。浏览器打开启动后显示的本地地址。需要支持 WebGL 的浏览器，推荐开启硬件加速。预览运行期间无需外部图片、在线字体或其他媒体服务。

```sh
pnpm test       # 玩法规则测试
pnpm build      # 生成 dist 生产版本
pnpm preview    # 预览生产版本
```

## 对原设计的分析与完善

GDD 的优势是主题集中：保留既有居民与建筑，把建设、政策和气候检验连成一次改造计划。其主要不足是费用、覆盖、回合结算、卡牌时效和失败补救尚未落到可验证规则。概念图中的多个绿化模块、太阳能和大型城市设施也超出了文档的首版范围。本原型补齐以下部分。

| 原有缺口 | 原型中的实现 | 对决策的影响 |
| --- | --- | --- |
| 公共绿化可能只按设施数量累计 | 按设施中心到住宅中心的平面距离判定，按实际居民加权，重叠服务去重 | 选址影响受益居民；在同一地区重复建设不能刷覆盖 |
| 屋顶与公园作用容易混淆 | 建筑绿化保护本栋室内，公共设施缓解户外；屋顶不产生公共覆盖 | 玩家需要安排两种投入，而非一种设施解决所有问题 |
| 抽牌可能决定硬目标能否完成 | 基本建设不耗政治点，阶段策略保证获得并保留；已验证无需出牌也可通关 | 随机政策提供节约和效率，不阻断基本通关路线 |
| 政策只是装饰性增益 | 批量绿化、长期公共工程协议、专项拨款三条策略路线；普通牌有当回合优惠、融资和应急支援 | 玩家可以选择不同资金与施工节奏 |
| 高温结果难以解释 | 逐栋居民快照，分别展示室内和户外热影响，再汇总宜居损失、财政支出和迁出人数 | 结果可以追溯到具体住宅与先前建设 |
| 财政可能失去约束 | 明确居民收入、基础运营、设施维护、融资利息、停车地转换费和高温支出 | 建设费用之外还需保留运营和应急资金 |
| 验收失败后容易滚雪球 | 原目标保留，两回合补救与一次小额支持；历史热浪成绩不改写 | 失败仍可继续调整，但不能无限延期 |
| 3D 只是背景，操作反馈不足 | 楼栋选取、地块预览、服务覆盖与热影响图层、即时外观改造、可访问的邻里名册 | 地图直接参与空间决策，界面明确目标与成本 |

## 当前情景规则

这些数值是用于平衡测试的原型参数，并非 GDD 中已确定的最终参数。

- 6 栋既有组屋，住房容量固定为 2,340 人，初始入住 2,050 人。103 为已绿化的示范住宅。建筑绿化不增加住房容量。
- 4 块可规划土地。西侧停车用地额外收取 $800 转换费。
- 初始资金 $12,500。每回合政治点恢复到 3。
- 主计划 8 回合。第 6 回合结束触发热浪，第 8 回合结束验收。未达标进入第 9–10 回合补救，期限不再延期。
- 验收目标：公共绿地服务覆盖至少 70%、至少 4 栋住宅绿化、社区宜居度至少 75。
- 建筑绿化费用 $1,800、维护 $45。社区公园费用 $3,200、半径 15、维护 $120。林荫步道费用 $1,900、半径 11、维护 $70。
- 每回合结束：收入 = $420 + 居民人数 × $0.55，扣除基础运营 $450、绿色设施维护及到期融资，再更新入住情况、事件与验收。开始新回合时刷新普通手牌与政治点。
- 3 选 1 的阶段策略直接加入手牌，需实施后才生效。每回合抽取 3 张普通政策；未使用的普通牌结束时弃置，保留策略跨回合持有。
- 公园的户外热影响低于步道。多设施重叠使用最佳户外保护，不重复叠加。应急支援只降低下一次高温损失，不增加永久公共覆盖。
- 各栋室内与户外热影响相加，按热浪时的居民人口加权后乘以 0.65，得到社区宜居度损失。财政支出与迁出人数分别结算。报告保留当时状态。
- 融资到账 $3,000，未来 3 次结算各偿还 $1,100；期末评价使用扣除未偿融资的净财政。
- 严重财政危机须连续两次结算低于 −$2,000 才终止，第一次提供预警。

公共覆盖按实际入住人口计算，因此入住变化也可能改变覆盖率。界面同时显示受益居民和总居民人数；施工预览显示本次新增覆盖，便于区分施工和人口变化。

## 操作

新玩家默认使用英文。顶部与各弹窗右上角的语言按钮可随时切换为中文或英文，当前浏览器会记住选择。切换不会重置进度、地图视角或选中目标；旧中文存档中的日志与报告也随界面切换。

点击住宅查看改造，点击空地选择设施。设施施工前显示总费用、受益楼号、公共覆盖增量与地图范围。地图可拖动平移、滚轮缩放，镜头保持等距方向。上方图层切换社区、公共服务覆盖和热浪风险；名册可直接选择所有住宅和土地。

选择阶段策略后，点击手牌查看完整政策规则并实施。目标政策先选择住宅，再确认使用。点击顶部财政查看收支、维护与未偿融资。结束回合会结算当前计划并自动保存。Esc 取消选址，设置中可重新开始。

存档保存在当前浏览器。禁止存储时会提示“保存不可用”，游戏仍可继续。无效旧存档安全回退到新计划。WebGL 不可用时保留地图错误提示与名册操作入口。

## 自然社区布局与规划 AI

住宅采用错落位置、不同朝向和宽深，社区内加入曲线路网、步行路径、树群与休憩节点。`src/layout.js` 是地图与经营规则共用的布局来源，服务半径仍按真实住宅中心距离计算。旧存档只迁移空间字段，保留资金、改造、手牌与历史热浪报告。

顶部的 **AI advisor / AI 顾问** 提供当前回合的方案比较：

- 使用游戏实际施工与政策规则，搜索最多 3 步的可行方案，最多评估 1,400 个候选，比较公共服务、热浪防护与财政空间。
- 同一起点展示覆盖、服务居民、热浪损失估计、余额、维护与债务的前后变化。历史热浪结果不受预测影响；未来抽牌、人口变化和回合结算不在搜索范围内。
- “查看第一步”只选择地图目标或打开政策确认，玩家仍须确认施工或实施政策。现金储备方案明确显示无需操作。
- 反思题根据当前目标缺口、热浪阶段与债务自适应选择。反馈解释覆盖去重、室内和户外措施、维护或融资的机制，首次答案保存在本局存档中，并与城市得分分开呈现。

此版本采用本地搜索规划 AI，无需密钥或外部模型。它提供局部搜索内的方案比较；学习题是练习反馈，教学效果需要玩家测试评估。

设计参考：Shute 的[形成性反馈研究](https://myweb.fsu.edu/vshute/pdf/shute%202007_f.pdf)、Conati 等的[智能教学中的可解释 AI 研究](https://arxiv.org/abs/1912.04464)。

## 验证

自动规则测试覆盖公共服务去重、建筑绿化边界、目标临界精度、常规通关、折扣失效、失败操作不扣费、策略保留、融资偿还、逐栋热浪与历史快照、存档恢复、补救期限和财政危机，并验证默认语言、旧存档双语显示和报告数值保留。

浏览器验证通过实际点击地图进行施工，检查预览与费用一致、图层切换、完整回合流程和存档恢复；另检查移动端排版、政策确认和失败补救流程。

## 后续迭代

当前版本聚焦 GDD 的首个可玩情景。完整能源需求与清洁电力区别、多阶段模块解锁、雨水花园与暴雨情景、新建住宅、复杂交通和成熟卡组构筑尚未实现。后续优先通过玩家测试调整财政强度、设施选择和卡牌收益，再增加内容。

游戏化半径、热影响与政策不代表真实新加坡行政流程或科学降温量。

## 项目结构

- `src/game.js`：不可变状态与独立玩法规则。
- `src/scene.js`：程序生成的 Three.js 社区、拾取、图层、动画与资源释放。
- `src/main.js`：双语界面、规则反馈、对话框与存档。
- `src/ui-locale.js`：界面翻译、语言偏好与即时切换。
- `src/engine-locale.js`：卡牌、日志与历史报告翻译，兼容旧存档。
- `src/layout.js`：共享空间布局与旧存档迁移。
- `src/advisor.js`：有界多步搜索、真实引擎证据与自适应反思题。
- `src/advisor-view.js`：双语方案比较与练习反馈界面。
- `src/icons.js`：原创界面图标与政策插画。
- `src/style.css`：桌面与移动布局。
- `tests/game.test.js`：玩法验证。
- `tests/locale.test.js`：语言与旧存档兼容验证。
- `tests/advisor.test.js`：建议合法性、证据重放、债务、未来抽牌隔离与双语验证。

技术参考：[Three.js 官方文档](https://threejs.org/docs/)。
